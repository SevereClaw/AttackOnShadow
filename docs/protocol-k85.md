# Протокол Attack Shark K85 (USB)

Восстановлено по коду официального драйвера Attack Shark Driver 2.1.79 (классы `MQt → mYe → zR → pR → tR → zA → NA → oA → Yj`; таблицу номеров команд для K85 задаёт класс `NA`, она переопределяет базовую из `Yj`) и сверено с двумя независимыми реализациями того же протокола Rongyuan: [debloatedfl-driver](https://github.com/Some1sm/debloatedfl-driver) (Rust, MIT) и [skillkorp-k20](https://github.com/ElMajor76/skillkorp-k20) (Python, MIT; у SkillKorp K20 тот же проводной VID/PID).

## Устройство

| | |
|---|---|
| VID / PID (провод) | `0x3151` / `0x4015` |
| HID-интерфейс | usage page `0xFFFF`, usage `0x0002` |
| Отчёт | feature report, 65 байт: `[0x00 report id] + 64 байта данных` |
| В драйвере | id 1949 или 1466, `yc3121_sg8948_dm_hall`, `magnetism: true`, `layer: 8`, `fnLayer: 1` |

Тот же PID у Swift 82 (`yc3121_swift82*_dm_hall`) — у неё тот же класс протокола.

Ниже индексы считаются **от первого байта данных** (без report id), как в коде драйвера.

## Контрольная сумма

`checksum = ~(сумма байтов 0..N−1) & 0xFF`, записывается в байт N.

- **BIT7**: N = 7 — для запросов и большинства команд.
- **BIT8**: N = 8 — для `SET_LEDPARAM` (цвет занимает байты 5–7).

## Обмен

- **Запись**: `HidD_SetFeature` с пакетом. Драйвер ждёт ~10 мс перед каждой записью.
- **Чтение**: записать запрос (`SetFeature`), подождать ~5–10 мс, прочитать `HidD_GetFeature`. Ответ: байт 0 — эхо команды, дальше данные.

## Слои (onboard-профили)

Индекс профиля 0..7. У хол-клавиатур на слой приходится 4 позиции (`h/=4`), поэтому пользователю видно **2 слоя**:

| Слой в интерфейсе | Индекс |
|---|---|
| Слой-1 | 0 |
| Слой-2 | 4 |

Позиции 1–3 и 5–7 используются для настроек хода клавиш (DKS и т. п.) внутри слоя.

- **SET_PROFILE** `0x05`: `[0x05, индекс, 0, 0, 0, 0, 0, cs]`, BIT7.
- **GET_PROFILE** `0x85`: запрос `[0x85, 0…, cs]` BIT7 → ответ `[0x85, индекс, …]`.

## Подсветка

- **SET_LEDPARAM** `0x07`: `[0x07, режим, 4 − скорость, яркость, опция, R, G, B, cs]`, **BIT8**. После записи драйвер ждёт 500 мс.
- **GET_LEDPARAM** `0x87`: запрос BIT7 → ответ `[0x87, режим, 4 − скорость, яркость, опция, R, G, B]`.

Яркость 0–4, скорость 0–4 (`MAXSPEED = 4`, на клавиатуру уходит `4 − скорость`).

**Опция**: младшие 4 бита — `7` (свой цвет, `NORMAL`) или `8` (радужный, `DAZZLE`). При чтении значения `0…6` в младших битах означают предустановленный цвет: красный, оранжевый, жёлтый, зелёный, голубой, синий, фиолетовый. Старшие 4 бита — вариант эффекта.

Белый `#FFFFFF` драйвер отправляет как `#FAFFFA` и при чтении показывает обратно белым.

| 0 | LightOff | — | — |
| 1 | LightAlwaysOn | — | да |
| 2 | LightBreath | — | да |
| 3 | LightNeon | — | нет |
| 4 | LightWave | вправо 0, влево 1, вниз 2, вверх 3 | да |
| 5 | LightRipple | — | да |
| 6 | LightRaindrop | — | да |
| 7 | LightSnake | Z 0, «туда-обратно» 1 | да |
| 8 | LightPressAction | — | да |
| 9 | LightConverage | — | да |
| 10 | LightSineWave | — | да |
| 11 | LightKaleidoscope | наружу 0, внутрь 1 | да |
| 12 | LightLineWave | вправо 0, влево 1 | да |
| 14 | LightLaser | — | да |
| 15 | LightCircleWave | против часовой 0, по часовой 1 | да |
| 16 | LightDazzing | — | да |

Режимы 13 (свой рисунок по клавишам), 20/22 (музыка) и 21 (цвет экрана) требуют программы, которая постоянно шлёт данные, — в первую версию приложения не входят.

## Проверено на живой K85

Журнал с настоящей клавиатуры (7 ноября 2026):

```
→ 05 04 00 00 00 00 00 F6        SET_PROFILE слот 4 (Слой 2)
→ 85 00 00 00 00 00 00 7A
← 85 04 00 00 00 00 00 7A        GET_PROFILE: слот 4
→ 87 00 00 00 00 00 00 78
← 87 04 02 04 08 B4 B4 B4        LEDPARAM: «Волна», скорость 4−2=2, яркость 4, радужный, цвет #B4B4B4
```

Ответ — эхо команды в байте 0 и данные дальше; на неизвестную команду K85 возвращает запрос без изменений.

**Осторожно с частотой запросов.** Если спросить клавиатуру (GET) примерно через 0,7 с после смены эффекта подсветки, прошивка зависает: дальше любой запрос, даже чтение, завершается `ERROR_GEN_FAILURE` (31), пока не переподключить кабель. Приложение после записи подсветки 2 с ничего не шлёт, а слой опрашивает не чаще раза в 5 с и не раньше 4 с после изменения.

## Таблица команд K85 (класс `NA`)

> Базовая таблица (`Yj`) отличается: там `0x02` = SET_PROFILE и `0x04` = SET_LEDPARAM. У K85 `0x02` — это **сброс**, а `0x04` — **частота опроса**. Клавиатура отклоняет незнакомые для неё GET-запросы (`ERROR_GEN_FAILURE`, 31) — так и нашлась эта разница.

| Команда | set | get |
|---|---|---|
| REV (версия прошивки) | — | `0x80` |
| RESET | `0x02` | — |
| BATTERY | — | `0x83` |
| REPORT (частота опроса) | `0x04` | `0x84` |
| PROFILE (слой) | `0x05` | `0x85` |
| KBOPTION | `0x06` | `0x86` |
| LEDPARAM (подсветка) | `0x07` | `0x87` |
| SLEDPARAM | `0x08` | `0x88` |
| KEYMATRIX | `0x09` | `0x89` |
| KEYENABLE | `0x0A` | `0x8A` |
| MACRO | `0x0B` | `0x8B` |
| USERPIC | `0x0C` | `0x8C` |
| INFOR | — | `0x8F` |
| DEBOUNCE | `0x11` | `0x91` |
| MAGNETISM_CAL / CALMAX / BY_ARR | `0x1C` / `0x1E` / `0x65` | `0x9C` / `0x9E` / `0xE5` |
